import { CardGrid, LinkCard, Card } from '@astrojs/starlight/components';

An agent needs a model to talk to. Which model is often not the agent
author's choice: a platform team standardizes on one vendor, a regulated
team keeps data on its own hardware, a cost review moves the cheap work
to a cheaper model. core-models is the piece that lets a Go agent reach
any of them the same way.

It is a library of **provider adapters** — the code that turns one
model request into the right API call for Gemini, Claude, OpenAI, a
Vertex AI partner model, or a model server you run yourself — plus the
**usage record** every adapter fills in, so cost and token counts look
the same whichever model answered.

## Who it is for

  <Card title="You build on mast or core-agent" icon="seti:go">

  </Card>
  <Card title="You embed ADK in your own Go service" icon="puzzle">

  </Card>
